# 팀 게이트 조건 (Team Gate Condition)

> **Status**: Approved
> **Created**: 2026-05-16
> **Layer**: Feature
> **Priority**: Vertical Slice
> **Pillar**: Pillar 3 — 팀이 곧 열쇠다 (Team Unlocks World)
> **Depends On**: NPC 상태 관리, 맵/지역 시스템

---

## 1. Overview

팀 게이트는 MapScene 안에 배치되는 Area2D 기반 노드로, 현재 파티 구성이 특정 태그 조건을
충족해야만 통과를 허용한다. 조건은 NPCRecord의 `recruitment_tags` 또는 `bond_tags`가
요구 목록과 일치하는지 여부로 판정한다. 조건 미충족 시 플레이어에게 시각적·텍스트 피드백을
제공하고 통과를 차단한다. 이 시스템이 Pillar 3 "팀이 곧 열쇠다"의 핵심 구현 단위다.

---

## 2. Player Fantasy

플레이어가 새로운 지역 입구에 다가서는 순간, "여기는 혼자 갈 수 없다 — 누군가가 필요하다"는
것을 직감한다. 그리고 며칠 전 영입한 동료 덕분에 막혔던 문이 열릴 때, 팀이 단순한 전투 자원이
아니라 세계를 여는 열쇠였다는 것을 깨닫는다.

영입이 선택이 아닌 탐험의 전제조건으로 느껴져야 한다. 차단 메시지는 힌트이지 처벌이 아니다.
"이 사람이 있으면 갈 수 있어"가 "이 사람이 없으면 못 가"보다 앞서야 한다.

## 3. Detailed Rules

### 3-1. 게이트 노드 구조

```
TeamGate_{id} (Area2D)
├── CollisionShape2D   ← 플레이어 감지 영역
└── GateLabel (Label)  ← 잠금 메시지 표시 (기본 숨김)
```

- `collision_layer = 0`, `collision_mask = player_body(2)` — 플레이어만 감지
- 그룹: `"team_gates"` — 월드 조건 시스템이 일괄 쿼리 가능하도록

### 3-2. 조건 판정

게이트는 `required_tags: Array[StringName]`와 `require_all: bool`을 보유한다.

| `require_all` 값 | 통과 조건 |
|-----------------|-----------|
| `true` (기본값) | 모든 태그가 파티에 존재 (AND) |
| `false`         | 하나 이상의 태그가 파티에 존재 (OR) |

판정 로직:

```gdscript
func _is_condition_met() -> bool:
    if required_tags.is_empty():
        return true  # 태그 없음 = 무조건 통과
    if require_all:
        for tag: StringName in required_tags:
            if not NPCRegistry.party_has_tag(tag):
                return false
        return true
    else:
        for tag: StringName in required_tags:
            if NPCRegistry.party_has_tag(tag):
                return true
        return false
```

### 3-3. 통과 허용 (조건 충족 시)

1. 게이트 Area2D 비활성화 (`monitoring = false`, `monitorable = false`)
2. GateLabel 숨김
3. `gate_opened(gate_id: StringName)` 신호 발행
4. 해당 포탈의 진입을 허용하거나 경로 충돌체 제거

### 3-4. 통과 차단 (조건 미충족 시)

1. 플레이어가 게이트 영역 진입 시 GateLabel 표시 (1.5초 후 자동 숨김)
2. 플레이어가 더 이상 진행하지 못하도록 게이트 충돌체 활성 상태 유지
3. 메시지 형식: `"[힌트 텍스트]"` — required_tags 기반 힌트 (예: "치료사가 필요하다")
4. `gate_blocked(gate_id: StringName)` 신호 발행 — 다른 시스템이 연출 추가 가능

### 3-5. 재판정 시점

- 플레이어가 게이트 영역에 진입할 때마다 실시간 재판정
- 씬 로드 직후(`_ready()`에서) 최초 판정 — 이미 조건이 충족된 경우 즉시 열림

### 3-6. MapScene 적용 규칙

- 게이트는 포탈 직전 또는 경로 상에 배치
- 포탈(Portal_{target})과 팀 게이트는 별개 노드 — 게이트가 열리면 포탈이 활성화됨
- 하나의 게이트가 여러 포탈을 제어하지 않는다 (1:1 관계 권장)

## 4. Formulas

### 조건 충족 판정 (AND 모드)

```
met = ∀ tag ∈ required_tags: NPCRegistry.party_has_tag(tag) == true
```

### 조건 충족 판정 (OR 모드)

```
met = ∃ tag ∈ required_tags: NPCRegistry.party_has_tag(tag) == true
```

### party_has_tag(tag) 내부 로직 (NPCRegistry 구현)

```
party_has_tag(tag) =
    ∃ record ∈ _companions_cache:
        tag ∈ record.recruitment_tags ∨ tag ∈ record.bond_tags
```

**예시 계산**:

- 파티: [서린 (tags: `["healer", "ranger"]`), 돌쇠 (tags: `["warrior"]`)]
- 게이트 required_tags: `[&"healer"]`, require_all: true
  → party_has_tag(&"healer") = true (서린) → **통과**

- 게이트 required_tags: `[&"mage"]`, require_all: true
  → party_has_tag(&"mage") = false → **차단**

- 게이트 required_tags: `[&"mage", &"warrior"]`, require_all: false (OR)
  → party_has_tag(&"warrior") = true (돌쇠) → **통과**

## 5. Edge Cases

| 상황 | 처리 |
|------|------|
| `required_tags`가 비어 있음 | 항상 통과 — 일반 지역 구분자로 사용 가능 |
| `required_tags`에 존재하지 않는 태그 포함 | `party_has_tag()` false 반환 → 영구 차단. 태그는 NPCRecord 정의에 존재해야 함 |
| 파티가 비어 있음 (동료 0명) | 모든 태그 조건 실패 → 차단 |
| 게이트가 열린 후 동료가 파티에서 제거됨 | 게이트는 이미 열린 상태 유지 (`monitoring = false` 고정) — 열린 문은 닫히지 않는다 |
| 동일 씬에 게이트 여러 개 | 각 게이트가 독립적으로 판정. 하나가 열려도 다른 게이트에 영향 없음 |
| 씬 전환 후 같은 씬으로 돌아옴 | `_ready()`에서 재판정 — 조건 충족이면 즉시 열림, 미충족이면 차단 유지 |
| DialogueManager.is_active 중 플레이어가 게이트 영역 진입 | 판정은 실행하되 GateLabel 표시만 억제 (대화 중 UI 중첩 방지) |

## 6. Dependencies

| 시스템 | 의존 방향 | 이유 |
|--------|-----------|------|
| NPCRegistry | 읽기 | `party_has_tag()` 호출로 파티 태그 조회 |
| 맵/지역 시스템 | 공존 | TeamGate는 MapScene 내 자식 노드로 배치 |
| 씬 전환 시스템 | 간접 | 게이트 열림 후 Portal 활성화 → SceneTransitionManager 연계 |
| DialogueManager | 읽기 | `is_active` 상태 확인 (GateLabel 표시 억제) |
| NPC 상태 관리 (NPCRecord) | 간접 | `recruitment_tags`, `bond_tags` 태그 시스템이 조건의 기반 |

**이 시스템에 의존하는 시스템**:
- 월드 조건 시스템 (inferred) — TeamGate 신호를 수신하여 지역 이벤트 트리거
- 팀 구성 기반 월드 잠금 해제 — 이 GDD가 해당 시스템의 핵심 구현 단위

## 7. Tuning Knobs

| 값 | 기본값 | 범위 | 영향 |
|----|--------|------|------|
| `required_tags` | `[]` | 0~3개 | 게이트 진입 조건 수. 3개 초과 시 조건 이해 난이도 급상승 |
| `require_all` | `true` | bool | AND/OR 모드 전환. OR 모드는 유연한 팀 구성 권장 시 사용 |
| GateLabel 표시 시간 | `1.5s` | `0.5s~3.0s` | 짧으면 힌트를 놓칠 수 있음; 길면 UX 거슬림 |
| 게이트 감지 반경 | 32px (default) | 16px~64px | 좁으면 트리거 타이밍이 예민; 넓으면 조기 판정 |
| 힌트 텍스트 | 태그별 정의 | — | 설계자가 태그→힌트 매핑 테이블 관리 |

**태그→힌트 매핑 예시** (별도 데이터 파일로 관리 권장):

| 태그 | 힌트 텍스트 |
|------|-------------|
| `healer` | "치료사가 필요합니다." |
| `warrior` | "강한 전사가 있어야 합니다." |
| `ranger` | "숲길을 아는 동료가 필요합니다." |

## 8. Acceptance Criteria

- [ ] **AC-1**: `required_tags = [&"healer"]`, 파티에 healer 태그 동료 있음 → 게이트 Area2D monitoring false, gate_opened 신호 발행
- [ ] **AC-2**: `required_tags = [&"healer"]`, 파티에 healer 태그 동료 없음 → 게이트 차단 유지, GateLabel 표시, gate_blocked 신호 발행
- [ ] **AC-3**: `required_tags = []` (빈 배열) → 항상 즉시 통과
- [ ] **AC-4**: `require_all = false` (OR 모드), `required_tags = [&"mage", &"warrior"]`, 파티에 warrior만 있음 → 통과
- [ ] **AC-5**: 게이트가 열린 후 파티에서 healer 동료 제거 → 게이트 닫히지 않음 (열린 상태 유지)
- [ ] **AC-6**: 씬 재진입 후 `_ready()` 실행 시 조건 충족이면 즉시 열림, 미충족이면 차단
- [ ] **AC-7**: DialogueManager.is_active == true 중 게이트 영역 진입 → 판정은 실행, GateLabel 표시 억제

## MapScene 적용 예시

```
# MapScene 노드 구성 (설계 기준)
MainMap (Node2D)
├── TileMapLayer
├── NavigationRegion2D
├── SpawnPoints (Node2D)
│   └── SpawnPoint_Default
├── TeamGate_forest_entrance (Area2D)   ← 팀 게이트
│   ├── CollisionShape2D
│   └── GateLabel (Label)
├── Portals (Node2D)
│   └── Portal_forest (Area2D)          ← 게이트 열림 후 활성화
└── EnemySpawnZones (Node2D)
```

```gdscript
# TeamGate 스크립트 핵심 흐름 (구현 참고)
@export var required_tags: Array[StringName] = []
@export var require_all: bool = true
@export var hint_text: String = ""
signal gate_opened(gate_id: StringName)
signal gate_blocked(gate_id: StringName)

func _ready() -> void:
    if _is_condition_met():
        _open_gate()
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node2D) -> void:
    if not body.is_in_group("player"):
        return
    if _is_condition_met():
        _open_gate()
    else:
        _show_blocked_feedback()
```
