## Purpose & Player Need

메인 메뉴는 플레이어가 유랑단 세계로 진입하는 단일 관문이다. 플레이어는 이 화면에서 새 게임을 시작하거나 이전 여정을 이어가고, 설정을 조정하거나 게임을 종료한다.

**플레이어가 이 화면에 도달했을 때 원하는 것**: "빠르게 게임 안으로 들어가기."

**핵심 액션 4개**:
- New Game — 새 여정 시작
- Continue — 이전 세이브 이어하기 (세이브 파일 없으면 비활성화)
- Settings — 입력 리바인딩 / 볼륨 / 접근성
- Quit — 게임 종료

**이 화면이 실패하면**: 플레이어가 게임 진입 전에 좌절하거나, Continue 버튼의 상태를 파악하지 못해 진행을 덮어쓸 위험이 있다. Continue 비활성화 패턴이 이 리스크를 제거한다.

---

## Player Context on Arrival

**첫 실행**: 플레이어는 설치 후 처음 게임을 켠다. 세이브 파일 없음. 기대감과 약간의 낯섦. 화면에는 New Game이 가장 눈에 띄는 위치에 있고 Continue는 비활성 상태로 존재한다. 감정 상태: 호기심, 탐색 준비.

**재실행**: 플레이어는 이전 세션이 있는 상태로 돌아온다. 세이브 파일 존재. "어디까지 했더라"는 복귀 심리. Continue가 New Game보다 시각적으로 강조(더 위, 더 크거나 더 밝게)되어 기본 선택지처럼 읽힌다. 감정 상태: 복귀, 재개 의지.

**두 상태 모두**: 플레이어는 자발적으로 이 화면에 도달했다 — 게임이 강제로 보낸 것이 아니다. 진입 의지가 있는 상태이므로 이 화면의 역할은 최대한 빠르고 명확하게 길을 열어주는 것이다.

## Navigation Position

메인 메뉴는 네비게이션 계층의 루트다. 부모 화면이 없으며, 게임 내 모든 진입 경로의 출발점이다.

`게임 실행 → [메인 메뉴]`

대체 진입 경로: 게임플레이 중 일시정지(Pause) → "메인 메뉴로 돌아가기" 선택 시.

## Entry & Exit Points

### Entry

| Entry Source | Trigger | 플레이어가 가져오는 컨텍스트 |
|---|---|---|
| 게임 실행 (첫 실행) | 앱 시작 | 세이브 파일 없음 — Continue 비활성 |
| 게임 실행 (재실행) | 앱 시작 | 세이브 파일 존재 — Continue 강조 표시 |
| Pause 메뉴 | "메인 메뉴로 돌아가기" 선택 | 진행 중 세션 — 미저장 진행 손실 경고 후 진입 |

### Exit

| Exit Destination | Trigger | 비고 |
|---|---|---|
| 게임플레이 씬 (New Game) | New Game 버튼 | 세이브 있으면 덮어쓰기 확인 팝업 필수 |
| 게임플레이 씬 (Continue) | Continue 버튼 (활성 시) | 세이브 로드 후 진입 |
| 설정 화면 | Settings 버튼 | 가역적 — Back으로 메인 메뉴 복귀 |
| 게임 종료 | Quit 버튼 | 비가역적 — 확인 팝업 없이 즉시 종료 (PC 표준) |

## Layout Specification

### Information Hierarchy

플레이어 시선 우선순위 (높음 → 낮음):

1. **배경 비주얼** — 실루엣 파티가 분위기를 먼저 설정
2. **게임 타이틀 / 로고** — 정체성 확인
3. **Continue / New Game** — 핵심 진입 액션 (세이브 유무에 따라 강조 순서 변경)
4. **Settings** — 보조 액션
5. **Quit** — 마지막 선택지
6. **버전 번호** — 보조 정보, 인지 부하 없음

### Layout Zones

**안 B — 좌하단 버튼 패널**: 배경 비주얼(실루엣 파티)은 화면 오른쪽 중앙~하단에 배치되어 버튼 영역과 겹치지 않는다. 타이틀은 좌상단, 버튼 그룹은 좌하단, 버전 번호는 우하단.

## States & Variants

| State | Trigger | 변경 사항 |
|---|---|---|
| **첫 실행 (Default)** | 세이브 파일 없음 | Continue 비활성(grayed out), New Game이 첫 포커스 |
| **재실행** | 세이브 파일 존재 | Continue 강조(더 크거나 더 밝게), Continue가 첫 포커스 |
| **덮어쓰기 확인** | New Game 버튼 + 세이브 파일 존재 | 확인 팝업 오버레이 등장, 배경 딤(dim) 처리, 팝업이 포커스 받음 |
| **로딩** | Continue 확정 또는 New Game 확정 후 | 눌린 버튼 텍스트가 "..." 로 변경, 모든 버튼 비활성, 씬 전환 시작 |
| **세이브 파일 없음** | 앱 시작, `SaveManager.has_save() == false` | Continue 비활성(Disabled Button 패턴), 포커스 시 툴팁 "저장된 기록이 없습니다" 표시 |
| **세이브 파일 손상** | `SaveManager.has_save() == true`, `load_save_data()` 파싱 실패 | Continue 비활성, 화면 진입 즉시 손상 확인 팝업 등장 (아래 상세) |
| **로드 실패** | `load_save_data()` 실행 중 IO/예외 오류 | 로딩 상태 해제, 에러 팝업 등장 — 다시 시도 / 새로 시작 선택지 |
| **메인 메뉴 복귀 — 저장 실패 후** | 게임플레이 중 자동저장 실패 후 메인 메뉴 진입 | Continue 비활성, Disabled Button 툴팁 "마지막 저장에 실패했습니다. 진행 상황이 복구되지 않을 수 있습니다." |

### 에러 상태 상세

**세이브 파일 손상**
- Continue 버튼 비활성화 (Disabled Button 패턴)
- 화면 진입 즉시 확인 팝업 등장:
  ```
  ┌─────────────────────────────────┐
  │  저장 파일을 불러올 수 없습니다.  │
  │  파일이 손상되었습니다.           │
  │                                 │
  │  [ 취소 ]      [ 새로 시작 ]    │
  └─────────────────────────────────┘
  ```
  - 취소: 팝업 닫힘, 메인 메뉴 유지 (Continue 비활성 상태)
  - 새로 시작: 손상 파일 삭제 후 New Game 흐름 진입
  - 첫 포커스: 취소 (Confirmation Dialog 패턴 — 안전한 기본값)

**로드 실패** (Continue 실행 중 IO/예외)
- 로딩 "..." 상태 해제
- 에러 팝업 등장:
  ```
  ┌─────────────────────────────────┐
  │  게임을 불러오는 데 실패했습니다. │
  │                                 │
  │  [ 새로 시작 ]  [ 다시 시도 ]   │
  └─────────────────────────────────┘
  ```
  - 다시 시도: 팝업 닫힘 → `load_save_data()` 재호출, 로딩 상태 재진입
  - 새로 시작: New Game 흐름 진입 (기존 세이브 삭제 여부는 손상 여부에 따라 분기)
  - 첫 포커스: 다시 시도 (데이터 손실 최소화 기본값)

## Transitions & Animations

**씬 진입**: SceneTransitionManager 페이드 인 (검정 → 화면). 배경 비주얼과 버튼이 페이드 완료 후 등장.

**씬 퇴장 (게임플레이 진입)**: SceneTransitionManager 페이드 아웃 (화면 → 검정). 로딩 "..." 표시 중 페이드 시작.

**씬 퇴장 (Settings)**: 페이드 없이 즉시 전환 — 설정은 오버레이 성격.

**배경 애니메이션**: 실루엣 파티 캐릭터들의 idle 애니메이션이 느린 속도로 재생 (아트 바이블 2.5 — "slow idle sway"). 씬 진입 시부터 루프.

**확인 팝업 등장**: 즉시 팝업 (애니메이션 없음, MVP 단순화). 배경 딤 처리는 Panel의 불투명도로 구현.

**모션 감소 모드**: 접근성 요건(Standard 티어) — 모션 감소 설정 활성화 시 페이드 트랜지션 및 idle 애니메이션 재생 속도 최소화.

| BGM 재생 | AudioManager | Write | 씬 진입 시 메인 메뉴 BGM 트랙 지정 |

## Accessibility

**접근성 티어**: Standard (committed — design/accessibility-requirements.md)

**키보드 탐색 경로**: Tab / ↑↓ → Continue → New Game → Settings → Quit (순환). 비활성 Continue는 Tab 순서에 포함하되 선택 불가.

**게임패드 탐색**: D-pad ↑↓로 버튼 간 이동. A버튼 확정, B버튼 취소/뒤로. 확인 팝업에서 B버튼 = 취소. (Steam Deck 필수)

**포커스 표시**: 모든 버튼에 명확한 포커스 인디케이터 필수. 마우스 호버 없이도 포커스 상태가 시각적으로 구분되어야 함.

**텍스트 대비**: 버튼 텍스트 4.5:1 이상 (WCAG AA). 비활성 Continue는 낮은 대비 허용 (비활성 상태 전달 목적).

**색상 단독 표시자**: Continue 활성/비활성 구분은 색상 + 불투명도(또는 텍스트 스타일) 병행 — 색상만으로 구분 금지.

**텍스트 크기**: 버튼 라벨 24px 이상 @ 1080p.

**모션 감소**: 배경 idle 애니메이션 + 씬 페이드 트랜지션은 모션 감소 모드 활성화 시 중지 또는 최소화.

**스크린 리더**: Godot 4.6 AccessKit — 버튼 포커스 시 라벨이 스크린 리더에 읽힘. 비활성 Continue는 "(사용 불가)" 상태를 레이블에 포함.

## Localization Considerations

**MVP 범위**: 한국어 단일 로케일. 다국어 지원은 Post-MVP이나 버튼 너비는 40% 텍스트 확장 여유를 두고 설계.

| 요소 | 현재 (한국어) | 최대 허용 길이 | 위험도 |
|---|---|---|---|
| Continue 버튼 | "이어하기" (4자) | 버튼 너비 기준 약 12자 | LOW |
| New Game 버튼 | "새 게임" (4자) | 버튼 너비 기준 약 12자 | LOW |
| Settings 버튼 | "설정" (2자) | 버튼 너비 기준 약 12자 | LOW |
| Quit 버튼 | "종료" (2자) | 버튼 너비 기준 약 12자 | LOW |
| 확인 팝업 본문 | "기존 저장 데이터를 삭제하고 새로 시작합니다. 계속할까요?" | 2줄 이내 | **MEDIUM** — 독일어/프랑스어 40% 확장 시 줄 넘침 가능 |

버전 번호는 로케일 무관 (숫자/점 표기 공통).

## Acceptance Criteria

- [ ] 게임 실행 시 메인 메뉴가 2초 이내에 완전히 표시된다 (BGM 포함)
- [ ] 세이브 파일이 없을 때 Continue 버튼이 비활성(grayed out) 상태로 표시되며 선택되지 않는다
- [ ] 세이브 파일이 있을 때 Continue 버튼이 활성화되고 New Game보다 시각적으로 강조되며 첫 포커스를 받는다
- [ ] New Game 선택 시 세이브 파일이 있으면 덮어쓰기 확인 팝업이 등장하고, "취소" 선택 시 메인 메뉴로 돌아오며 포커스가 New Game으로 복원된다
- [ ] Tab / ↑↓ 키보드 입력만으로 4개 버튼 전체를 탐색하고 선택할 수 있다
- [ ] D-pad ↑↓ + A버튼만으로 게임패드 탐색 및 선택이 완전히 동작한다 (Steam Deck 기준)
- [ ] 모든 버튼에 포커스 인디케이터가 마우스 호버 없이도 표시된다
- [ ] Settings 버튼 선택 시 설정 화면으로 이동하고, Back으로 메인 메뉴에 돌아왔을 때 Settings 버튼에 포커스가 복원된다
- [ ] Quit 버튼 선택 시 확인 없이 즉시 게임이 종료된다
- [ ] 모션 감소 모드 활성화 시 배경 idle 애니메이션이 재생되지 않는다
